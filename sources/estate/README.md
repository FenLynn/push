# Estate 数据源维护说明

## 数据边界

`EstateSource` 只保存可核验的官方成交、供应和价格数据。最新结果覆盖固定 KV 键
`dashboard:snapshot:estate:latest`；时间序列和项目级公示写入现有 Push D1，不新增数据库。

三类数据不得混用：

- **成交**：某日已经网签/成交的套数与面积。
- **供应**：某日新发预售许可证涉及的项目和可售楼幢，不代表成交。
- **价格**：国家统计局 70 城价格指数，不代表成交均价。

缺失数据保持缺失，不能写成 `0`。只有官方页面明确返回的零值才保存为零。

## 当前来源

### 成都成交

- 来源：成都市住建蓉 e 办“商品房当日成交”公开网关。
- 适配器先取得服务器时间，再按网页公开的 HMAC-MD5 规则请求每日数据。
- 时间接口会根据 `Accept` 返回 JSON 或 XML；适配器同时兼容两种格式，避免官网内容协商变化导致整条链路失效。
- 必须优先选择 `region_type=全市` 的汇总行；只有旧结构没有该字段时才回退到最大汇总行并记录警告。
- 输出新房、二手房的成交套数和面积，质量标记为 `official`。
- 不使用账号、Cookie 或浏览器登录态。
- `queryDate` 当前会被官网忽略并返回最新日期，因此只能从修复后的每日任务开始连续积累，不能用该接口补齐漏采的历史日。

### 西安成交

- 来源：西安市住房和城乡建设局“二手房网签情况”月度公开信息。
- 通过住建局站内搜索读取每月官方摘要；摘要缺字段时仅回访对应官方正文，不访问商业房产平台。
- 当前可回溯至 2022 年 8 月，保存存量房网签总面积、住宅网签套数和住宅网签面积。
- 该来源是**月度二手房成交**，西安市住建局公开站点未发现可稳定读取的每日新房/二手房成交汇总接口。
- 月度成交写入 `transactions` 组并标记 `frequency=monthly`，不得与预售许可证数量相加。

### 西安供应

- 来源：西安市住房和城乡建设局“商品房预售项目公示”：
  `https://zjj.xa.gov.cn/ygsf/index.aspx`。
- 输出每日预售许可证数、项目数、可售楼幢数。
- 每张预售证同时写入 D1 `estate_events`，保存预售证号、项目、地址、开发企业、楼幢、发证日期和原始链接。
- 公示是稀疏事件。没有新发许可证的日期不补零。
- 住建局页面偶尔返回防护页；首页失败时整条来源降级，后续分页失败时保留已经核验的页面，不影响成都链路。

### 成都 / 西安价格

- 来源：国家统计局 70 城住宅销售价格指数，经 AkShare 读取。
- 保存新房/二手房环比、同比月度指数，质量标记为 `official`。
- 该指标用于观察价格方向，不与成交套数、预售供应相加或互相替代。

## 历史迁移

旧版 `SecondHand_Count_Anjuke` 实际来自房天下移动页挂牌总量，既不是官方成交，也存在
重复房源和页面口径变化。自本迁移起：

- 不再抓取和续写该序列；
- 不再放入最新 KV 快照；
- D1 旧记录保留用于审计，不删除、不回填、不视为当前可信指标；
- 旧的实验性 Finance 图可能在历史窗口内读取旧记录，但默认实验指标关闭。

## 存储

- `estate_daily`：兼容旧查询的日指标表。
- `data_series` / `data_observations`：规范化趋势；每个分类使用独立 series ID。
- `estate_events`：西安官方预售项目级公示。
- KV：只有最新快照和最近 12 条许可，不累积历史垃圾。

日频保留 3 年，过期前按月聚合；官方月度价格指数长期保留。项目公示通过
`(source, external_id)` 去重更新。

## 降级与维护

单个来源失败时，可展示 7 天内最后一次有效快照，并保留原始 `sourceDate`、标记
`stale: true`；旧值不会伪装成当天记录写回 D1。

修改任一 provider 时至少执行：

```powershell
python -m pytest tests/test_data_archive.py tests/test_dashboard_snapshot.py -q
```

还应分别实测成都 `_scrape_chengdu()` 与西安 `_scrape_xian_presales()`。不要因为两个城市都属于
房产模块，就合并它们各自的请求、解析或错误判断。
